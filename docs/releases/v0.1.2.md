# RTMP Stream Monitor 0.1.2

This patch release adds compressed API responses for larger timeline payloads and records a repeatable SQLite capacity benchmark for a multi-stream deployment.

## Included

- Central Docker image `ghcr.io/sadoharu/rtmp-stream-monitor:0.1.2`; Compose now uses this version by default.
- HTTP gzip compression for responses of 1,000 bytes and larger. Browsers negotiate compression automatically.
- SQLite capacity benchmark for four streams and forty probes, covering one hour of raw samples and seven days of minute aggregates. In the recorded local Docker Desktop run, gzip reduced a seven-day response from about 25.6 MB to 1.61 MB while retaining all 99,150 points.
- Migration preflight now inventories every SQLite table, including `probe_enrollments`.
- Windows ZIP and Ubuntu 22.04 `.deb` probe packages with SHA-256 sidecars, rebuilt through the tagged release workflow.

## Verification limits

- Python test suites, Windows and Ubuntu package lifecycle checks, Docker migration/backup/rollback fixtures, and the 40-probe capacity workload run in CI.
- The SQLite capacity measurement uses sequential requests and synthetic data on a local Docker Desktop Linux backend. It is not a production-host SLA and does not test concurrent ingestion.
- The existing Ubuntu systemd database has not yet been migrated on the target server; production rollback and installation on separate customer machines remain unverified.
- Independent-site fault localization and Windows TCP EStats under controlled packet loss/reordering remain open. The application keeps incident causes unconfirmed when required observations are missing.
- The Windows package is not code-signed.
