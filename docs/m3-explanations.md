# M3 — пояснення подій та інцидентів

**Статус: каталог подій, детерміновані пояснення й відображення доказів перевірені на API та production-збірці dashboard.** Пояснення працюють локально за правилами; OpenAI лишається окремою явною дією оператора для інцидентів.

## Що повертає API

`GET /api/v2/streams/{stream_id}/events` повертає probe-події та інциденти на спільній часовій шкалі. Для probe-події API надає короткий український підсумок, пояснення відповідно до коду й ролі probe, лише дозволені числові докази з одиницями та `UNCONFIRMED`. Невідомий код отримує нейтральний підсумок замість показу сирого коду як пояснення.

Інциденти містять детерміновані `cause_key`, рівень упевненості, вибрані докази, можливі альтернативи й наступні перевірки. Рівні рушія `low/medium/high` зіставляються з `UNCONFIRMED/LIKELY/CONFIRMED`. Відповідь не викликає OpenAI. Довільний текст події, FFmpeg stderr, токени та поля поза allowlist не передаються до картки події чи AI-пакета.

## Покриття кодів і вимірів

- Каталог `_safe_events` покриває коди, які створюють FFmpeg/analyzer, SRS ingress, correlation та мережеві виміри: зокрема `FREEZE_*`, `SILENCE_*`, `KEYFRAME_GAP_END`, `FFMPEG_*`, `PROBE_ERROR`, `AV_TIMESTAMP_DRIFT`, `SRS_*` та `INGRESS_RECOVERED`.
- Підсумок і пояснення розділяють проблему медіа та проблему спостереження. `SRS_API_UNAVAILABLE`, `SRS_COUNTERS_UNAVAILABLE` і `SRS_PUBLISH_STATE_UNAVAILABLE` означають, що стан входу невідомий; самі по собі вони не доводять збій потоку. `INGRESS_RECOVERED` означає відновлення SRS спостереження, а не успішне декодування медіа.
- `DEEP` може декодувати кадри й повідомляє `DECODE_ERROR`; `LIGHT` лише читає пакети через `ffprobe`, тому відповідна помилка розбору позначається як `BITSTREAM_PARSE_ERROR`, а не як помилка декодера.
- `KEYFRAME_GAP` показує фактичний час без ключового кадру, поріг і доступний очікуваний GOP. `STREAM_STALL` показує доступний вік медіа/ingress та поріг. Події `FFMPEG_DEAD`, `FFMPEG_EXIT`, `FFMPEG_RESTART`, `PROGRESS_STALE` і `PROBE_ERROR` пояснюють стан процесу спостереження та не оголошують його кореневою причиною потоку.
- Для SRS ingress картка може показати доступність API, стан публікації, вік останнього руху, приймання за 30 секунд, байти й лічильники кадрів.
- У UI тривалість `SILENCE_DURATION` називається тривалістю тиші, а `FREEZE_DURATION` — завмиранням. Булеві докази локалізовані; невідомі коди інцидентів не з'являються в інтерфейсі як сирі snake-case рядки.
- Пояснення мережевих доказів українською описують межі Linux per-flow, Windows host-wide retransmit і ICMP RTT вимірів. Вони не називають ICMP-втрату прямим виміром втрати RTMP-пакетів.

## Перевірки

- `tests/test_event_catalog.py` вимагає, щоб кожен відомий producer code був у AI allowlist і мав людський підсумок; перевіряє передачу дозволених чисел та відсікання тексту/секретів.
- `tests/test_api.py` проходить від створення probe та ingest до V2 events API для `SRS_COUNTERS_UNAVAILABLE` і `KEYFRAME_GAP`; перевіряє пояснення, часові докази, одиниці виміру та відсутність приватного payload.
- Наявні тести API, explanations і SRS окремо покривають `CLIENT_PROBLEM`, PTS regression, network signal, `AGENT_OFFLINE`, FREEZE інтервали та SRS відновлення.
- `python -m pytest -q`: повний набір пройшов; є один пропущений тест.
- `npm run typecheck` і `npm run build`: пройшли; збірка React оновила production assets, які віддає FastAPI.

## Межі висновків

Пояснення є висновком за вимірами та їхньою часовою якістю, не forensic-гарантією. Без одночасних source/ingress/egress/client вимірів система має залишати причину непідтвердженою. Цей аудит не замінює незалежну перевірку на фізичному Ubuntu-сервері та окремих клієнтських мережах; ці runtime-перевірки залишаються частиною M6.
